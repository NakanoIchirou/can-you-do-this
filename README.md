# can-you-do-this

一个帮助用户结构化拷问 AI 项目承诺的轻量 Skill。

把“我有一个灵感”变成能讨论的推进流程，讲清每一段的难点、当前 AI 能力、免费与付费路线、时间预算，以及用户必须亲自做的事。默认分析，不自动制作。

## 它会回答什么

- 这件事大概怎么推进，最容易卡在哪里？
- 当前会话的模型、工具、素材和预算，能支持到什么质量？
- 免费渠道和付费渠道分别能换来什么？
- 哪些必须由用户提供、操作、判断或复核？
- 应该马上推进、慢慢做、暂时搁置，还是放弃当前路线？
- 下一轮该怎样具体追问 Astra、Chat 或其他 AI？

SSM 用于澄清不同参与者的目的，霍尔三维用于检查阶段、决策和知识缺口，WSR 用于检查资源、流程和人的配合。它们帮助发现遗漏，不用来制造虚假的精确工期。

## 安装和调用

将本仓库下载或克隆为目标项目中的 `.agents/skills/can-you-do-this/`，保留 `SKILL.md` 和 `references/` 的相对位置。用技能选择器确认本地环境已发现，再调用：

```text
$can-you-do-this 我想做一部动画。先帮我分析大概流程、首次难点、你实际能做到什么、免费和付费路线，以及我必须亲自做什么。先分析，不要制作。
```

```text
$can-you-do-this 下面是另一个 AI 的方案。请拆开它的承诺，核查关键事实，给出明确建议，并给我三到五个能追问它的问题：[粘贴方案]
```

不能加载本地 Skill 的聊天环境，可以上传 `SKILL.md`，并按需附上参考文件，要求按文件分析。这属于提示词使用，不等于账号已安装或同步。工具不足时，Skill 要求明确标记尚未验证的事实。
